**核心结论：完整操作系统不只是内核。内核负责受保护地管理资源与执行，用户态基础系统负责组织服务与程序运行，系统产品层负责安装、使用、维护和恢复。**

“完整”由目标用途和可验证的系统契约定义，不要求实现本文列出的所有可选功能。

## 1. 系统边界与组成范围

| 范围 | 包含什么 | 解决的问题 |
|---|---|---|
| 内核 Kernel | CPU 调度、内存管理、中断、系统调用、基础 IPC，以及架构决定放入内核的驱动、文件系统、网络等 | 安全地复用硬件资源，隔离不同执行主体 |
| 基础操作系统 | 内核、启动组件、系统库、初始进程、基础服务与工具 | 让程序运行起来，让系统可管理 |
| 完整系统产品 | 基础系统、安装、更新、恢复、安全策略、软件管理、用户界面和诊断 | 让用户可以安装、使用、维护与升级 |
| 应用生态 | 浏览器、数据库、办公软件、开发工具等 | 满足业务需求，通常不属于操作系统核心 |

边界说明：

- UEFI、BIOS、设备固件通常是操作系统之外的基础设施。
- Bootloader 经常随系统交付，但不是内核。
- Shell、桌面、登录界面属于用户态。
- 驱动、文件系统和网络栈的位置由系统架构决定，不必全部位于内核态。
- 安全、同步、诊断、资源控制和错误处理贯穿多个层次。
- Linux 严格说是内核；Linux 发行版将内核与用户态系统及维护工具组合成系统产品。

## 2. 整体层次结构

下面是概念分层，不要求实现时只能逐层调用。某些模块还会同时跨越多个层次。

| 层次 | 名称 | 主要模块 |
|---|---|---|
| L7 | 应用与系统工具 | 普通应用、管理工具、开发工具、诊断工具 |
| L6 | 用户交互与系统产品 | Shell、桌面、登录、软件管理、安装、更新、恢复 |
| L5 | 用户态系统服务 | init、服务管理、网络配置、认证、日志、设备管理、时间同步 |
| L4 | 用户态运行环境 | 系统库、动态链接器、语言运行时支持、进程启动环境 |
| L3 | 系统调用、IPC 与 ABI 边界 | 用户态请求内核或其他受保护服务 |
| L2 | 内核资源与服务 | 任务、调度、内存、文件、I/O、网络、权限、隔离 |
| L1 | 架构支持与硬件控制 | 异常、中断、页表、CPU 启动、时钟、总线、驱动 |
| L0 | 启动衔接 | Bootloader、启动协议、早期初始化、根文件系统切换 |
| 外部基础 | 硬件与固件 | CPU、RAM、设备、UEFI、设备固件 |

横向能力：安全与权限、同步与并发、资源配额、错误传播、可观测性、兼容性。

## 3. 启动与系统初始化

### 3.1 启动链

```text
固件初始化
  → 选择启动设备
  → Bootloader
  → 装载内核与初始数据
  → 内核早期初始化
  → 建立内存、中断与调度环境
  → 初始化必要设备
  → 挂载根文件系统
  → 启动第一个用户态进程
  → 启动系统服务
  → 登录或运行应用
```

### 3.2 子模块

| 子模块 | 职责 |
|---|---|
| 启动协议适配 | 接收内存地图、启动参数、显示信息、固件表等 |
| 内核镜像装载 | 装入内核，必要时解压和重定位 |
| 初始文件系统 | 可选：提供找到真正根文件系统所需的早期组件 |
| 早期输出 | 在正式驱动和日志尚未就绪时输出错误 |
| 早期内存分配 | 为页表、启动数据等提供临时分配机制 |
| CPU 执行环境建立 | 设置栈、异常入口、映射及相关寄存器 |
| 子系统初始化 | 按依赖顺序初始化内存、时钟、中断、调度、设备等 |
| 多核启动 | 唤醒其他 CPU，建立每核状态 |
| 根文件系统发现 | 找到系统盘、解密卷或网络根并挂载 |
| 用户态启动 | 创建初始用户进程，启动服务体系 |

**边界与依赖**：启动模块将机器带到可运行状态，之后由正常的资源管理模块接管。可以利用现成固件与 Bootloader，不必重写通电后的全部流程。

## 4. CPU 架构支持与硬件抽象

这一层把具体 CPU 机制转换成内核能够使用的接口。

### 4.1 CPU 与执行上下文

| 子模块 | 职责 |
|---|---|
| 特权级管理 | 建立用户态、内核态及访问边界 |
| 寄存器上下文管理 | 保存、恢复寄存器、指令位置和栈指针 |
| 浮点与向量状态 | 隔离线程的 FPU、SIMD 等状态 |
| 每 CPU 数据 | 保存本核当前线程、运行队列、统计信息 |
| 特性检测 | 检测指令、页表、安全与虚拟化能力 |
| 多处理器拓扑 | 识别核心、硬件线程、缓存关系和 NUMA 节点 |
| CPU 热插拔 | 可选：运行中上线、下线 CPU，迁移任务 |

### 4.2 内存与设备访问机制

| 子模块 | 职责 |
|---|---|
| 页表操作 | 建立、修改、撤销虚拟地址映射 |
| TLB 管理 | 清除失效地址转换 |
| 跨核 TLB 失效 | 防止其他 CPU 继续使用旧映射 |
| 缓存与内存属性 | 区分普通内存、设备内存、不可缓存区域等 |
| 内存屏障 | 约束 CPU 与编译器重排 |
| 原子操作 | 提供不可分割的共享状态更新 |
| MMIO、端口 I/O | 访问设备寄存器 |
| DMA 支持 | 处理设备访问内存所需的地址与缓存一致性 |

**边界与依赖**：上层调度、内存、中断、驱动依赖这些接口。HAL 是硬件抽象思想，不保证每个系统都存在独立的 HAL 模块。

## 5. 中断异常与时间系统

### 5.1 中断与异常

| 子模块 | 职责 |
|---|---|
| 异常入口 | 处理缺页、非法指令、除零、权限错误等同步异常 |
| 外部中断入口 | 接收设备产生的异步中断 |
| 中断控制器 | 配置路由、屏蔽、优先级与中断结束 |
| 中断分发框架 | 注册并调用相应处理函数 |
| 延后处理 | 将不适合在硬中断中执行的工作移交其他上下文 |
| 核间中断 IPI | 通知重新调度、TLB 更新、停止执行等 |
| 特殊中断 | 处理不可屏蔽中断、机器检查等 |
| 用户态异常转换 | 将程序错误转换为信号、异常通知或终止 |
| 内核故障处置 | 处理内核异常，必要时 panic 与转储 |

### 5.2 时间与定时器

| 子模块 | 职责 |
|---|---|
| 时钟源 | 提供计数，用于测量经过的时间 |
| 时钟事件设备 | 在指定时间触发事件 |
| 单调时间 | 用于超时、间隔和性能测量，避免墙上时间跳变影响 |
| 墙上时间 | 提供日期与时间，可被校时调整 |
| 高精度定时器 | 提供较精细的超时和唤醒 |
| 定时器队列 | 管理多个待到期事件 |
| 无周期 tick | 可选：减少不必要的周期时钟中断 |
| CPU 时间记账 | 统计线程、进程使用的 CPU 时间 |
| RTC 衔接 | 读取硬件实时时钟 |
| 校时接口 | 支持时间服务调整时间或校正频率 |

**关键区别**：时钟源回答“计数是多少”，时钟事件设备负责“到那个时间叫醒我”。经过时间不应随意用可校时的日历时间计算。

## 6. 内核基础设施与并发同步

| 子模块 | 职责 |
|---|---|
| 基础数据结构 | 链表、树、哈希表、位图、队列等 |
| 原子变量 | 安全更新共享计数和状态 |
| 自旋锁 | 保护不能睡眠的短临界区 |
| 互斥锁 | 保护允许阻塞等待的临界区 |
| 读写同步 | 协调多读者与写入者 |
| 信号量 | 控制有限资源的并发访问 |
| 等待队列 | 让线程等待事件并被唤醒 |
| 完成量、事件对象 | 表达异步操作完成或状态变化 |
| RCU 类机制 | 可选：支持低开销读取与延迟回收 |
| 引用计数 | 管理共享对象生命周期 |
| 工作队列 | 在可调度上下文中执行延后任务 |
| 对象注册与查找 | 管理设备、驱动、文件系统等对象 |
| 内核模块管理 | 可选：运行中装载、卸载扩展 |
| 并发诊断 | 检测锁顺序问题、竞态与非法睡眠 |

**执行约束**：某些中断上下文不能睡眠；持有自旋锁时通常不能阻塞；共享对象释放前必须证明没有残余访问者。几乎所有内核子系统都依赖这一层。

## 7. 进程线程与调度

**进程管理执行环境，线程承载执行流，调度器决定哪个执行流何时使用 CPU。**

### 7.1 进程与线程管理

| 子模块 | 职责 |
|---|---|
| 进程对象 | 管理地址空间、资源集合、身份和父子关系 |
| 线程对象 | 管理上下文、内核栈、状态和调度属性 |
| 创建与克隆 | 创建进程或线程，定义共享哪些资源 |
| 程序替换 | 将执行映像替换为新程序 |
| 退出与回收 | 关闭资源、发布退出状态、回收对象 |
| 父子关系与等待 | 支持等待子进程结束 |
| 进程组与会话 | 支持终端作业控制等组织关系 |
| 线程局部存储支持 | 提供线程独立运行时数据的定位 |
| 暂停与恢复 | 支持调试、作业控制等 |
| 身份与资源继承 | 定义权限、句柄和限制的继承规则 |

### 7.2 调度器

| 子模块 | 职责 |
|---|---|
| 可运行队列 | 管理能够执行的线程 |
| 调度策略 | 在公平、优先级、实时性、吞吐之间取舍 |
| 抢占 | 在适当时机切换当前线程 |
| 上下文切换 | 切换寄存器、栈及必要地址空间状态 |
| 睡眠与唤醒 | 协调等待 I/O、锁与定时器的线程 |
| 多核负载均衡 | 避免 CPU 工作分布失衡 |
| CPU 亲和性 | 限定或倾向执行所在 CPU |
| NUMA 感知 | 减少跨节点内存访问 |
| 实时调度 | 可选：支持有时限要求的任务 |
| 优先级继承 | 缓解低优先级持锁者阻塞高优先级线程 |
| 调度组与配额 | 限制用户、服务或容器的 CPU 使用 |
| 空闲线程 | 无工作时进入空闲或节能状态 |

**依赖**：上下文切换依赖架构层；超时依赖时钟；阻塞与唤醒依赖同步机制。实时保证还需要中断、锁、驱动等协同，不等于单纯提高优先级。

## 8. 内存管理

### 8.1 物理内存

| 子模块 | 职责 |
|---|---|
| 物理内存地图 | 区分可用、保留、固件和设备区域 |
| 物理页分配器 | 分配、释放物理页，处理连续页需求 |
| 内存区域划分 | 满足 DMA、地址范围、NUMA 等约束 |
| NUMA 管理 | 可选：按节点分配、迁移与统计 |
| 大页支持 | 可选：减少页表和 TLB 开销 |
| 内存热插拔 | 可选：动态增加、移除内存 |
| 坏页与硬件错误 | 隔离损坏页面，处置内存硬件故障 |

### 8.2 虚拟内存

| 子模块 | 职责 |
|---|---|
| 地址空间 | 提供进程独立的虚拟地址视图 |
| 虚拟内存区域 | 记录映射范围、权限和来源 |
| 匿名映射 | 提供堆、栈等不直接对应普通文件的区域 |
| 文件映射 | 将文件内容映射到地址空间 |
| 按需分页 | 实际访问时才建立或装入页面 |
| 缺页处理 | 判断访问是否合法并完成必要操作 |
| 写时复制 COW | 写入时才创建共享页面的私有副本 |
| 共享映射 | 让多个进程访问相同物理页 |
| 页面保护 | 控制读、写、执行与用户态访问 |
| 映射撤销 | 协调页表、TLB 和对象生命周期 |
| 页面固定 | 防止特定页面被回收或迁移 |

### 8.3 分配器与内存压力

| 子模块 | 职责 |
|---|---|
| 内核堆、对象分配器 | 分配不同大小的内核对象 |
| 虚拟连续分配 | 提供虚拟连续但物理不必连续的区域 |
| 页缓存 | 缓存文件内容，减少存储读取 |
| 回收策略 | 释放可回收缓存和页面 |
| Swap | 可选：将部分页面移到后备存储 |
| 脏页回写 | 将修改后的文件页写回 |
| OOM 处置 | 明确定义分配失败时的拒绝、终止或恢复策略 |
| 配额与统计 | 限制并观察服务或进程组的使用 |
| 分配器诊断 | 检测越界、释放后使用、重复释放等 |

**三个不同模块**：物理页分配器管理 RAM 页面；内核对象分配器管理较小对象；虚拟内存管理器管理地址映射与保护。只有堆分配器不代表内存管理完成。

## 9. 系统调用 ABI 与程序装载

### 9.1 系统调用与对象接口

| 子模块 | 职责 |
|---|---|
| 系统调用入口 | 安全进入内核态 |
| 调用分发 | 按编号或接口标识选择处理函数 |
| 参数检查 | 检查长度、标志、地址、句柄等 |
| 用户内存访问 | 安全读取或写入用户空间并处理失败 |
| 句柄、文件描述符表 | 把进程持有的标识映射到受控对象 |
| 权限检查 | 判断调用者能否操作对象 |
| 返回与错误契约 | 表达成功、失败、部分完成 |
| 取消与重启 | 处理阻塞操作被事件中断 |
| 兼容层 | 可选：支持旧 ABI 或不同位宽程序 |

### 9.2 程序装载与运行环境

| 子模块 | 职责 |
|---|---|
| 可执行格式解析 | 识别 ELF、PE 等及其元数据 |
| 段映射 | 建立代码、数据、只读区域 |
| 初始栈 | 设置参数、环境变量和启动信息 |
| 入口设置 | 决定程序开始执行的位置 |
| 动态链接器 | 可选：用户态装载共享库、重定位与符号解析 |
| 系统库 | 把应用 API 转换成系统调用或用户态操作 |
| 基础运行环境 | 提供内存分配、字符串、文件、线程等接口 |
| ABI 稳定性 | 固定调用约定、数据布局和兼容规则 |

**区别**：API 是程序使用的接口；ABI 是编译后的二进制约定；系统调用只是部分 API 的实现方式。全静态系统可以没有动态链接器，也不必兼容 POSIX，但要有明确契约。

| 回滚 | 新版本故障时恢复旧版本 |
| 恢复环境 | 主系统不能启动时提供修复入口 |
| 备份还原 | 保存用户数据与必要状态 |
| A/B 槽位 | 可选：更新备用系统后切换 |
| 工厂恢复 | 可选：恢复产品初始状态 |

**完整性要求**：更新必须考虑中断、断电、依赖冲突、不可启动和数据格式迁移。包管理器可裁剪，但软件如何交付与更新必须有答案；系统版本回滚不自动等于用户数据也能回滚。

## 22. 典型跨模块协作路径

以下展示常见路径，不是所有系统和所有模式的唯一实现。

### 22.1 启动程序

```text
Shell 或服务管理器
  → 请求创建执行环境
  → 创建进程、线程与资源
  → 解析可执行文件
  → 建立代码、数据、栈映射
  → 必要时启动动态链接器
  → 调度线程
  → 返回用户态执行
```

涉及系统调用、进程、文件系统、内存、ABI、调度与安全。

### 22.2 读取本地文件

```text
应用 read()
  → 系统库与系统调用
  → 查找文件描述符
  → 检查访问和状态
  → VFS 与具体文件系统
  → 查询页缓存
       ├─ 命中：交付数据并返回
       └─ 未命中：
            → 块 I/O
            → 存储驱动与设备
            → 完成被中断或轮询发现
            → 填充缓存
            → 唤醒等待线程
            → 交付数据并返回
```

文件读取不一定每次访问磁盘，也不一定每次触发设备中断。

### 22.3 合法缺页

```text
CPU 访问虚拟地址
  → 缺页异常
  → 异常入口
  → 虚拟内存检查
       ├─ 非法：报告进程错误
       └─ 合法：
            → 分配页面、从文件装入或执行 COW
            → 更新页表与必要的 TLB 状态
            → 返回并重试原指令
```

缺页可以是按需分页的正常机制，不一定是程序错误。

### 22.4 网络收包

```text
网卡收包
  → DMA 写入受控缓冲区
  → 中断或轮询发现
  → 驱动处理
  → 协议栈解析
  → 找到连接或 Socket
  → 放入接收队列
  → 发送就绪或完成通知
  → 唤醒或通知应用
  → 应用获取数据
```

涉及内存、DMA、中断、驱动、网络、调度、事件和安全。

## 23. 宏内核微内核与模块部署位置

| 架构 | 内核侧通常包含 | 用户态通常包含 | 主要取舍 |
|---|---|---|---|
| 宏内核、单体内核 | 调度、内存、IPC，以及较多驱动、文件系统、网络服务 | 库、系统服务、工具、应用 | 内部调用方便，但内核可信代码较多 |
| 微内核 | 最基本的执行、地址空间、IPC、中断和保护机制等 | 许多驱动、文件系统、网络服务 | 隔离边界清楚，通信与资源协调复杂 |
| 混合架构 | 按产品需要保留较多服务，采用模块化或服务化设计 | 部分系统服务与扩展 | 性能、兼容和隔离折中 |

- 宏内核可以高度模块化。
- 微内核完整系统的功能并不一定少，只是部署位置不同。
- 性能不能仅由架构名称推断，要看通信、数据路径、批处理和负载。
- 模块数量不能代替安全证明，权限与生命周期边界更重要。

## 24. 最小运行与完整可用的分界

| 阶段 | 必要能力 | 能证明什么 |
|---|---|---|
| 能启动的内核 | 入口、执行环境、早期输出 | 内核获得控制权 |
| 能运行任务的内核 | 内存、中断、时钟、任务切换、同步 | 可组织多个执行流 |
| 有用户态的 OS | 地址隔离、系统调用、装载、基础 IPC | 可运行受保护程序 |
| 基础可用 OS | 文件、必要设备、库、init、控制入口 | 可完成基本操作 |
| 目标平台完整 OS | 满足目标的网络、安全、服务、安装、更新、恢复、诊断 | 可在限定用途长期使用 |
| 成熟通用 OS | 广泛软硬件兼容、产品能力、充分验证与维护 | 可承担复杂长期负载 |

这是能力阶段示意，不是强制实现顺序，也不是已批准的 ElaraOS 里程碑。

- 服务器可以没有桌面，但不能缺少其业务所需的网络、安全、服务监督和恢复。
- 嵌入式系统可以没有进程、虚拟内存、包管理，但必须满足承诺的实时性、设备控制与可靠性。
- 桌面系统缺少输入、图形、应用环境、安装和恢复时，强内核也不能弥补产品不完整。

**能启动不等于能使用；能使用不等于能长期维护；模块代码存在不等于系统契约已经验收。**

## 26. 术语与官方核验入口

### 26.1 关键术语

| 术语 | 含义 |
|---|---|
| Kernel | 管理受保护执行与系统资源的内核 |
| ABI | 二进制调用、数据布局及兼容约定 |
| IPC | 进程间通信 |
| MMIO | 通过内存地址访问设备寄存器 |
| DMA | 设备直接访问内存的数据传输机制 |
| TLB | 缓存地址转换的处理器结构 |
| NUMA | 内存访问代价随节点位置不同的架构 |
| VFS | 统一文件系统接口与命名对象框架 |
| COW | 写时复制 |
| OOM | 内存不足状态及其处置 |
| QoS | 资源或服务质量控制 |
| DAC / MAC | 自主访问控制 / 强制访问控制 |
| ACL | 访问控制列表 |
| ASLR | 地址空间布局随机化 |
| IOMMU | 设备内存访问的地址转换与隔离机制 |
| TTY / PTY | 终端 / 伪终端 |
| FUA | 请求设备使该次写入满足相应持久化语义的机制 |

### 26.2 官方资料入口

以下资料用于进一步核验具体机制；列出入口不表示本文已经按其当前版本逐条核验。

- [Linux 内核文档](https://docs.kernel.org/)：内存、调度、驱动、文件系统、网络、管理与开发文档；代表 Linux 的实现与接口，不代表所有 OS。
- [POSIX / The Open Group Base Specifications Issue 8](https://pubs.opengroup.org/onlinepubs/9799919799/)：标准系统接口与工具语义；不要求每个 OS 都兼容。
- [UEFI Specifications](https://uefi.org/specifications)：固件、启动与相关规范入口；固件不等于操作系统。
- [ACPI Specifications](https://uefi.org/specifications)：硬件描述与电源管理规范入口，按目标平台选择版本。
